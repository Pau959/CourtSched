// 03
Results, Discussion & Recommendations

Key Issues & Recommendations

Based on the analysis of SUS scores, task performance data, and participant feedback, the following issues and design recommendations are proposed to improve the CourtSched prototype.

// 03.01
Key Issues Identified

What needs to be fixed

Six primary usability issues were identified through participant feedback and task performance analysis — ranked by priority based on frequency of mention and impact on task completion.

01
Small and poorly placed interactive elements — Time slot buttons and tap targets are too small, causing difficulty especially for users with larger hands. Button placements are not intuitive, leading to confusion during the court reservation task.
Task 02 — Court Reservation Nielsen H3: User Control Nielsen H5: Error Prevention
High Priority
02
Slow response time and system delays — Participants reported minor lag during page transitions and after completing actions, which negatively impacted the perception of system quality and responsiveness.
All Tasks Nielsen H1: Visibility of System Status
High Priority
03
Lack of feedback and confirmation messages — The system does not provide adequate confirmation after completing actions (e.g., saving a profile edit or submitting a booking), leaving users uncertain about whether their actions were successful.
Task 02, Task 06 Nielsen H1: Visibility of System Status
High Priority
04
Accessibility settings are not discoverable — Several participants could not easily locate the accessibility settings panel. The feature lacks visual prominence, making it inaccessible to users who need it most.
Task 01 — Accessibility Settings Nielsen H6: Recognition over Recall
Medium Priority
05
Color palette inconsistencies and readability issues — The color choices received mixed feedback, with some users finding contrast insufficient or the color application inconsistent across screens, affecting visual clarity.
All Tasks Nielsen H4: Consistency & Standards
Medium Priority
06
No onboarding guidance for first-time users — Users unfamiliar with digital scheduling systems — particularly older adults and those with limited tech literacy — lacked step-by-step guidance to get started with the system.
All Tasks Nielsen H10: Help & Documentation
Medium Priority
// 03.02
Design Recommendations

Recommended design improvements

Six concrete design improvement recommendations, mapped to the usability issues identified — each grounded in established HCI principles and participant feedback.

// REC 01
Increase Button Size & Improve Layout

Redesign interactive elements — particularly time slot buttons and action controls — to meet minimum touch target guidelines (at least 44x44px). Reorganize button placement to follow a logical, predictable layout that aligns with user expectations. Group related actions visually and ensure sufficient spacing between clickable elements to prevent accidental taps.

Minimum 44px Touch Targets Logical Button Grouping Visual Hierarchy Fitts's Law
// REC 02
Add Clear Confirmation & Feedback Messages

Implement visible system feedback after every key user action — including success confirmations, loading indicators, and error messages with actionable guidance. After submitting a court reservation, the system should display a clear confirmation screen with booking details. After saving a profile edit, a success toast or banner should appear immediately. This directly addresses Nielsen's Heuristic #1 (Visibility of System Status).

Success Confirmations Loading Indicators Toast Notifications Nielsen H1
// REC 03
Optimize System Performance

Address the reported response delays by optimizing page transition speeds, reducing unnecessary load times, and implementing skeleton loaders or transition animations to indicate progress. Where possible, leverage client-side caching and lazy loading to improve perceived performance. Even cosmetic improvements such as smooth transitions can significantly reduce user frustration during waiting periods.

Skeleton Loaders Lazy Loading Page Transitions Client-Side Caching
// REC 04
Improve Accessibility Settings Visibility

Relocate the accessibility settings to a more prominent position — ideally accessible directly from the main navigation or as a persistent floating button. Use a recognizable icon (such as the universal accessibility symbol) with a clear label. Consider offering a first-launch prompt that encourages users to configure their accessibility preferences before using the system for the first time.

Universal Accessibility Icon Persistent Shortcut First-Launch Prompt Nielsen H6
// REC 05
Refine Color System & Typography

Conduct a thorough color audit to ensure WCAG AA compliance across all text-background combinations. Establish a consistent color system with defined roles — primary actions, status indicators, backgrounds — and apply them uniformly across all screens. Increase font size for court details on the home page, and ensure body text maintains a minimum 4.5:1 contrast ratio for readability across all lighting conditions.

WCAG AA Compliance 4.5:1 Contrast Ratio Consistent Color Roles Nielsen H4
// REC 06
Add Onboarding & Feature Enhancements

Introduce a brief, skippable onboarding flow for first-time users that highlights the system's core features — particularly the court booking and calendar view. Add language selection options to support non-English-proficient users. Implement a waitlisting feature for cancelled reservations, and consider adding court preference memory to streamline the rebooking experience for returning users.

Onboarding Walkthrough Language Options Waitlisting Feature Preference Memory Nielsen H10

// 03.04
Conclusion

Overall Assessment

The CourtSched prototype demonstrates strong foundational usability with a 100% task completion rate and a System Usability Scale score of 68.00 — Grade C (OK). All 40 participants successfully completed their assigned tasks within the allotted time, confirming that the system's core architecture is accessible and learnable.

Viewing tasks — particularly View Notification (4.8/5) and View Schedule (4.7/5) — achieved the highest satisfaction scores, demonstrating that the system's information display design is well-executed. The calendar feature, transparent scheduling, and minimal interface design were consistently praised.

However, interactive tasks — especially the court reservation workflow — revealed opportunities for improvement in button layout, touch target sizing, system feedback, and performance. With targeted improvements focused on the six identified issues, the next iteration of CourtSched can realistically target a Grade A (Excellent) SUS rating.

"The CourtSched prototype performs well across all six tasks. With focused improvements to feedback messages, button sizing, and onboarding, the system is well-positioned to achieve excellent usability in its next iteration."

— Group 7 Final Assessment
